# 실행 설명 — 파도와 물결 (KOWAS-EPI 4611)

## 1. 구성

| 파일 | 내용 |
|---|---|
| `model.py` | 제출 모델 (`Model` 클래스). 보조 모듈 없음 |
| `requirements.txt` | 외부 라이브러리: `numpy>=1.24` |
| `predictions.csv` | `evaluation.py backtest`로 만든 평가 창 10개 전체 예측 (2,159행) |

학습된 가중치, 패널·전국 집계 수치, 보조자료(`auxdata/`)는 패키지에 들어 있지 않습니다. 제출 설정에서 모델 코드는 `evaluation.py`가 넘겨주는 `rows`만 쓰며 어떤 파일도 직접 읽지 않습니다(기상 실험 코드는 꺼져 있음, §6).

## 2. 실행 환경

- 개발 환경: Windows 11, Python 3.12.12, numpy 2.3.5
- 확인 환경: 새 가상환경(Python 3.12)에 `requirements.txt`만 설치(numpy 2.5.4)해 실행했고, 개발 환경과 `predictions.csv`가 바이트 단위로 같았습니다.
- 네트워크: 모델 코드에 네트워크 호출이나 파일 읽기가 없습니다. 네트워크를 물리적으로 끊은 상태의 실행은 따로 해 보지 않았습니다.
- 대회 제안 환경(Python 3.11, CPU 8코어, GPU 없음)에서 문제없이 동작하도록 numpy 기본 연산만 씁니다.
- 실행 시간: 평가 창 10개 합계 약 20~25초(창당 1.4~2.5초, 노트북 CPU 기준). 2026-11-06 재현에서는 창당 1.7~2.5초, 합계 약 23초였습니다.
- 2026-11-06 재현: `requirements.txt`만 설치한 별도 가상환경(numpy 2.5.4)에서 최종 정량점수 0.3005, `predictions.csv` SHA-256 `fc36162e…cf7cb`가 제출본과 같았습니다(기록: 저장소 `runs/repro_20261106/`).

## 3. 실행 방법

`KOWAS-EPI` 폴더에서 실행합니다. 이 제출 폴더가 `../submit`에 있다고 가정합니다.

```bash
# 가상환경 (Windows는 .venv\Scripts\python.exe)
python -m venv .venv
.venv/bin/python -m pip install -r ../submit/requirements.txt

# 평가 창 10개 백테스트 → predictions.csv, score.json
.venv/bin/python evaluation.py backtest --model ../submit/model.py --out ../submit/predictions.csv --json ../submit/score.json

# 형식·점수 확인
.venv/bin/python evaluation.py score ../submit/predictions.csv
```

기대 출력: `최종 정량점수 (평가 창 10개 평균) = 0.3005`

## 4. 재현성

- 난수를 쓰지 않습니다. 로지스틱 회귀도 0에서 시작하는 고정 반복(경사하강 800회)이라 같은 입력이면 같은 예측이 나옵니다.
- 같은 명령을 두 번 실행해 `predictions.csv`가 바이트 단위로 같은 것을 확인했습니다.
- 평가 창 사이에 전역 상태나 디스크 캐시를 쓰지 않습니다.

## 5. 모델 요약

log10 농도를 `시·도 수준 + 전국 공통 유행파 + 지역 편차 + 측정 잡음`으로 봅니다.

- **공통 유행파(파도)**: 시·도 수준을 뺀 뒤의 주별 평균. 최근 26주로 시·도 수준을 추정하며 반복 분해합니다.
- **t+2주 농도**: `시·도 수준 + 공통파 + phi·2주 추세 + rho·s(n)·현재 편차`. `s(n) = n/(n+k)`는 처리장 수(n_sites)가 적은 주의 편차를 더 줄이는 가중입니다(k = 0이 골라지면 꺼짐). 지역 편차와 측정 잡음은 따로 추정하지 않고 함께 줄입니다.
- **급증 경보**: 로지스틱 분류기(입력 6개: 예측의 경보선 대비 여유, 현재 농도의 기준 대비 위치, 자기 1주 변화, 공통파 추세, 공통파 대비 위치, 처리장 수)의 확률이 임계값 이상이면 1.
- **하이퍼파라미터 선택**: `fit` 안에서 학습 구간 마지막 52개 원점으로 롤링 검증해 `w, phi, rho, k`를 고르고(공식 창 점수와 같은 산식), 경보 분류기와 임계값은 학습 구간 전체 원점으로 학습합니다. 특정 주차·연도·평가 창을 가리키는 조건문이나 값 표는 없습니다.
- 관측이 전혀 없는 시·도는 원점 주차까지의 마지막 `conc_3wk_avg`로 대체합니다(공식 기준선과 같은 방식). 평가 키 2,159개에서는 이 경로가 한 번도 쓰이지 않았습니다.

## 6. 외부 자료와 기상 결합 코드

제출 설정(`WEATHER = "off"`)에서는 외부 자료·보조자료·정적 CSV를 하나도 쓰지 않습니다.

`model.py`에는 ASOS 기상 결합 실험에 쓴 코드가 남아 있습니다(`attach_weather`, `WEATHER` 설정). 규정대로 동작합니다.
- 기상 일자료는 `evaluation.py`가 넘기는 `aux` 인자로만 받습니다(기준 주 이하).
- 처리장·관측소 좌표는 허용된 정적 파일(`KOWAS_STATIC_DIR`의 `plant_meta.csv`·`asos_stations.csv`)에서만 읽습니다. `first_sample_week ≤ 해당 주`인 처리장만 씁니다.
- 실험 결과 기상을 넣은 4가지 설정 모두 점수가 낮아서(0.2910~0.2957) 제출 설정에서는 꺼 두었습니다. 기상을 꺼도 `aux` 인자를 받는 것만으로는 예측이 바뀌지 않는 것을 확인했습니다.
